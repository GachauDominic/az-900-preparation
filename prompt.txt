NOTES: AUTHORING RULES (every notes.md)
- Written from scratch in your own words. Never copy or closely paraphrase
  Microsoft Learn text, and never reproduce real exam questions or dumps.
- Fixed sections, in this order: "What you will learn" (each bullet tagged with
  its objective id), "Key ideas", "How it looks in real life", "Compare and
  contrast" (a table of easily confused things), "Exam tips", "Quick recap",
  "Go deeper" (links on learn.microsoft.com only), and a final line
  "Last reviewed: YYYY-MM-DD".
- 500 to 900 words. Current product names only (Microsoft Entra ID, Microsoft
  Defender for Cloud, Microsoft Purview). Anything that changes often (prices,
  limits, offer terms) is described in general terms with "check Microsoft Learn".
- Every objective in syllabus.json is taught in the notes.

QUESTIONS: AUTHORING RULES (every questions.json)
- At least 12 per module, and at least one per objective. More objectives means
  more questions. Mix: single answer, choose-two ("Select two."), and yes/no
  statement sets (a three-statement item is correct only if every statement is
  right). About 40 percent should be short scenarios.
- Fields: id (M05-Q07), module, objective_id, type (single, multi, yesno),
  difficulty, prompt, options, correct, explanation, why_wrong (every wrong
  option, or every statement for yesno), learn_more (learn.microsoft.com URL),
  reviewed (false by default).
- Plausible distractors drawn from commonly confused real services. No "all of
  the above" or "none of the above". Negatives only in capitals (NOT).
- Option ids appear in the page source, so the correct id must NOT be
  predictable: generate options and then randomise which letter is correct with
  a seeded shuffle at authoring time. A test must fail if every single-answer
  question has the same correct letter.
- Option order is also shuffled at render time with a per-attempt seed.
- Correct answers, explanations and links must never appear in the page source
  before the learner checks or submits.

APP BEHAVIOUR
1. Home: course overview grouped by domain, each domain linking to its Learn path;
   a progress bar and best score per module; "Continue where you left off";
   links to the exam simulation; "Reset my progress".
2. Module page: sticky table of contents on wide screens, a line linking the
   matching Microsoft Learn module, "Mark notes as read", buttons for the
   practice quiz and the exam-style quiz, and Previous and Next module links.
3. Practice mode: the learner presses "Check answer" and sees the explanation
   and the reason each wrong option is wrong, with no page reload.
   Exam-style mode: no feedback until the end.
4. Grading is server-side and deterministic. Results show the score, a score by
   objective, which objectives or modules to revisit (under 70 percent), an
   explanation for every question, and a "Next module" button after a module quiz.
5. Exam simulation: 40 questions, 45-minute countdown that submits itself, pass
   mark 70 percent, a clear "practice only, not an official Microsoft exam"
   notice. Share questions between domains by the weights in syllabus.json
   (largest-remainder apportionment per domain, then equal split across the
   domain's modules), capped by questions available.
6. A review gate: when REQUIRE_REVIEWED=1 only questions with reviewed:true are
   served; locally everything is shown with an "Unreviewed" badge.
7. Progress in localStorage only, with try/catch around every access.

VALIDATOR (scripts/validate_content.py, exit code 1 on any error)
Fail on: missing notes or required sections or "Last reviewed" line; fewer than 12
questions; unknown or duplicate ids; id not prefixed with its module; an objective
with no questions; wrong correct-count for the question type; fewer than 4 options
for single and multi; "all/none of the above"; missing explanation or why_wrong;
non-learn.microsoft.com links in notes, learn_more, learn_module or learn_path.
Warn on: unreviewed questions, planned modules, outline not verified.

TESTS (pytest, all data-driven, never hard-code a module's question count or a
particular correct letter)

module (12 distinct Learn modules); correct letters vary; grading of all three
types including partial and empty answers; answer parsing ignores unknown ids;
display strips answers and is reproducible per seed; exam plan follows domain

every module page and both quiz modes load; quiz pages leak no explanations or
links; perfect and empty submissions; the exam flow; /api/check; XSS escaping;
rate limiting and the review gate; Learn links shown on home and module pages.
